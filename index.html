Color

Remap channels with matrices and transfer curves. Cheap, predictable, and the safest place to start. Always set color-interpolation-filters="sRGB" so your hex values come out as designed.

Texture

feTurbulence generates Perlin noise on the fly, so textures cost no image requests. Blend it over the content and clip it back to the source alpha.

Blur & distortion

feGaussianBlur spreads each pixel over its neighbours; feDisplacementMap moves each pixel by the value of a map, usually noise, with scale as the strength in pixels. Both affect edges: blurred and displaced borders can go transparent, so the kit enlarges the --bg copy for these filters.

Shape

Work on the alpha channel to change silhouettes: merge, thicken, thin or outline.

Light & depth

Lighting primitives treat alpha or noise as a surface and shine a distant, point or spot light on it. This is where bevels, embossing and metallic sheen come from.

Fill & compositing

feComposite with in, out, atop or arithmetic combines layers like Photoshop masks. Here a generated texture is masked by the text shape.

Glass

filter only touches an element's own pixels. Glass has to process what lies behind it, so it uses backdrop-filter. Plain CSS functions work everywhere; an SVG filter reference in backdrop-filter renders only in Chromium. Both classes come with the kit's assets/svg-filters.css.

Motion

Primitive attributes aren't CSS properties, so CSS transitions can't reach them. Animate with SMIL <animate> inside the filter (markup only, synchronized for every element using it) or set attributes from JavaScript for hover and pointer effects; the kit's assets/svg-filters.js does the latter and pauses all animation under reduced motion and in hidden tabs. Animated filters re-render every frame.

Using the kit

Install

Add the module as svg-filters/ in your child theme (git subtree, submodule, clone or release zip; see the README), then load it from functions.php: 

require_once get_stylesheet_directory() . '/svg-filters/svg-filters.php';

Classes

  • Every <filter id="fx-…"> in filters/ becomes two classes: .fx-name filters the whole element, .fx-name--bg only its background.
  • The loader prints all filters once before </body> (wp_footer); url(#id) resolves document-wide.
  • To add a filter, save a copied file (or your own) as filters/name.svg. <title>, <desc> and the data-* attributes are optional; they only feed this page.

Tuning filters

Tune it on each card lists the values worth changing, with a sensible range, and lets you try them on the live swatch. Copy … with these values gives you the file with your values filled in; save it in filters/. The values are plain attributes, so you can also edit them in the file directly. Knobs most filters share:

  • Pixel values (stdDeviation, scale, radius, dx/dy) don't scale with the element. Tune them at the real size.
  • Noise. baseFrequency sets the grain of feTurbulence: lower is larger. Two values are horizontal and vertical. numOctaves adds detail (and cost); seed picks another, equally stable pattern.
  • Colors (flood-color, lighting-color) take any CSS color. Color tables (tableValues) use 0–1 per channel: divide the 8-bit value by 255.
  • Filter region. If an effect gets cut off at the edges, widen x, y, width and height on the <filter>.
  • Variants. To use one filter twice with different values (say two duotones), copy the file and give the filter a new ID; you get new classes for it.

Divi

Where the classes go

  • CSS class. Add it under Advanced → CSS ID & Classes → CSS Class of a section, row or module.
  • Divi's own Filters setting (Design → Filters) writes its own filter: on the module and overrides the class. Leave it at defaults, or put the class on a child element.
  • --bg uses ::before. On normal backgrounds the kit places a filtered copy of the background in ::before, behind the content. Don't use it on elements where Divi or your CSS already styles ::before.

Parallax backgrounds

  • True Parallax (JS) works with --bg: the filter goes on the span that holds the image, .et_parallax_bg in Divi 4 and .et-pb-parallax-background in Divi 5.
  • CSS Parallax (background-attachment: fixed) is not supported: a filter on that element can make Chrome drop the fixed behaviour.
  • Defs in the footer. Divi fires wp_body_open inside discarded output buffers, so the kit prints its filters in wp_footer only.

Getting it right

  • sRGB interpolation. Without color-interpolation-filters="sRGB", colors are computed in linearRGB and look washed out.
  • Filter region. The default region is the element plus 10%. Widen x/y/width/height for outlines, glows and offsets, or they get clipped.
  • Unique IDs. IDs are global per page. Prefix them (fx-) so they never collide with plugins; across the kit's files the first one wins.
  • Units. Pixel values (stdDeviation, scale, radius) don't scale with the element. Tune them at real sizes.

Keeping it fast

  • Area is the cost. Turbulence, lighting and displacement scale with pixel count. Use them on cards and images, not full-viewport sections.
  • Animation multiplies it. Every animated frame re-rasterizes the whole filter chain. Keep animated filters few and small.
  • Pause off-screen. An IntersectionObserver can toggle the class or call pauseAnimations().
  • Reduced motion. Under prefers-reduced-motion: reduce, pause SMIL and skip JS-driven effects. The kit and this page do both.
  • Test Safari. It is the slowest renderer for SVG filters on HTML content, especially on iPhones.
